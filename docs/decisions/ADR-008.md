# ADR-008: Guided Integration Roadmap & Boundary Architecture for BRICK-008 through BRICK-012

> **Status**: APPROVED (Owner Architecture Directive)  
> **Date**: 2026-11-02  
> **Deciders**: Project Owner & Principal Architect  
> **Impact Area**: BRICK-008 (Browser & Auth Nav), BRICK-009 (Memory & Qdrant RAG), BRICK-010 (Managed MCP Ecosystem), BRICK-011 (Advanced Tasks & Subagents), BRICK-012 (English & Arabic Voice)  

---

## 1. Context & Problem Statement

As Project **Javed (New JARVIS)** advances through Stage 4 (BRICK-007: Crawl4AI & Docling Extraction Pipeline), the system requires clear architectural baselines, integration boundaries, security controls, evaluation requirements, and phased delivery plans for future milestones BRICK-008 through BRICK-012.

Without a binding architecture directive, development risks architectural drift, dependency bloat, premature adoption of unvetted community packages, overlapping frameworks, and violation of core governance rules (Rule 1 FOSS-First, Rule 2 Anti-Bloat, Rule 4 Security & Sandboxing, Rule 7 Honesty in Status Tracking).

On 2026-11-02, the Project Owner issued the binding **Owner Architecture Directive: Guided Integration Roadmap for BRICK-008 through BRICK-012**. This ADR formally records that directive.

---

## 2. Global Architecture Principles

All architectural designs across BRICK-008 through BRICK-012 must strictly enforce:
1. **FOSS-First**: Prefer locally deployable, inspectable, open-source components. OpenRouter remains the sole preapproved proprietary paid service, accessed via replaceable adapters.
2. **Anti-Bloat**: Exactly one primary component per capability. Overlapping frameworks (multiple browser runners, competing memory databases, redundant subagent runtimes) are strictly prohibited without proving distinct, necessary capabilities.
3. **Existing Architecture First**: Extend JAVED's established components before introducing new layers: LangGraph state machine, Deep Agents runtime, `SecureMCPGateway`, `PositiveToolAllowlistMiddleware`, `ApprovalStore`, SQLite checkpointing, deterministic Playwright engine, Browser Preview Panel, Crawl4AI/Docling contracts, `NormalizedDocument` schema, and provenance hashes.
4. **Default-Deny**: All external tools, MCP servers, browser profiles, accounts, memory writes, subagents, microphones, audio exports, and mutating actions are denied until explicitly authorized.
5. **Read-Only by Default**: Read actions are strictly segregated from mutating actions (sending, deleting, modifying, submitting, purchasing). Mutating operations require single-use, fail-closed Human-in-the-Loop (HITL) approval.
6. **Secrets Never Enter the Model**: The language model, prompts, tool outputs, checkpoints, telemetry, logs, normalized documents, RAG stores, and reports must never receive credentials, cookies, tokens, passkeys, passwords, OTPs, or auth headers.
7. **Human Takeover, Not Security Bypass**: Logins, MFA, passkeys, and CAPTCHAs must trigger native JAVED owner takeover. Automated CAPTCHA solving, stealth patches, fingerprint spoofing, and residential proxy rotation are strictly prohibited.
8. **Reproducibility**: Version pinning, bounded direct dependencies, lockfile resolution, and documented licenses.
9. **Natural Teardown**: Zero `os._exit` calls. Idempotent cleanup of all browser instances, subagents, MCP servers, audio streams, and background processes.
10. **Evidence Before Promotion**: Evaluation candidates (Mem0, Stagehand) and reference-only architectures (Browser Use, VoxBigBrain, AI_assist, enhanced-mem-vector-rag) must not become production dependencies without empirical evaluation and Project Owner approval.

## 3. Approved Integration Decisions by Brick

### 3.1 BRICK-008: Browser Use and Authenticated Navigation
- **Primary Deterministic Browser Foundation**: Microsoft Playwright, Microsoft Playwright MCP, native JAVED browser tools, and the existing Browser Preview Panel.
- **Primary Authenticated Session Candidate**: OpenCLI (`opencli`) connecting to a dedicated JAVED Chrome profile.
- **Evaluation-Only Candidate**: Stagehand (`stagehand`) for semantic element discovery where deterministic selectors fail.
- **Reference-Only Architecture**: Browser Use (`browser-use`) for multi-step reasoning patterns (reference only; not a direct dependency).
- **Takeover Authority**: Native JAVED owner takeover for MFA, logins, and CAPTCHAs.
- **OpenCLI Boundary**: Model never receives raw CLI or shell access; constrained OpenCLI adapter drives dedicated JAVED profiles (`work-outlook`, `personal-outlook`, `work-gmail`, `personal-gmail`, `google-analytics`, `general-research`). Everyday Chrome profile access is strictly prohibited.
- **Tools**: Segregated read-only (`authenticated_page_read`, `mail_list_messages`, etc.) and single-use approval-gated mutating tools (`mail_send`, `authenticated_form_submit`, etc.).

### 3.2 BRICK-009: Persistent Memory and Semantic RAG
- **Primary Orchestration**: LangGraph.
- **Canonical Input**: BRICK-007 `NormalizedDocument`.
- **Primary Vector-Store Candidate**: Qdrant.
- **Personal-Memory Evaluation Candidate**: Mem0 (evaluation only).
- **Local Structured-Memory Foundation**: LangGraph Store and SQLite where appropriate during local development.
- **Reference-Only Architecture**: `BjornMelin/enhanced-mem-vector-rag`.
- **Primary Chunking**: JAVED deterministic provenance-aware chunker.
- **Embeddings**: Benchmark-selected English and Arabic embedding model.
- **Optional Retrieval**: Sparse lexical retrieval, metadata filtering, multilingual reranking.
- **Trust Boundary**: Direct writes to Qdrant prohibited from crawlers, browsers, Docling, and MCP servers. All indexing must originate from verified `NormalizedDocument` or governed memory writes.
- **Memory Governance**: Model inferences must not silently become trusted facts. Categorized memory writes with full user inspection, editing, and deletion controls.

### 3.3 BRICK-010: Managed MCP Ecosystem
- **Control Plane**: Official MCP Registry (`modelcontextprotocol/registry`) for primary public discovery; GitHub MCP Registry for secondary discovery; JAVED Private MCP Registry as authority; `SecureMCPGateway` for execution.
- **Authorization States**: `DENIED`, `ALLOWED_READ_ONLY`, `APPROVAL_REQUIRED`.
- **Admission Pipeline**: Mandatory multi-stage review (publisher verification, license, package hash, schema fingerprinting, owner approval). Unknown tools default to `DENIED`.
- **Initial Approved MCP Servers**: Playwright MCP, Time MCP, GitHub MCP, Context7 MCP.
- **Conditional Candidates**: DBHub, Notion MCP, MarkItDown MCP (require concrete use case, security review, and owner authorization).
- **Not Enabled by Default**: Generic shell, generic filesystem, Desktop Commander, arbitrary remote servers.

### 3.4 BRICK-011: Advanced Tasks and Subagents
- **Primary Subagent Framework**: Deep Agents on LangGraph.
- **Supporting Architecture**: BRICK-009 memory/RAG, BRICK-010 managed MCP, JAVED HITL `ApprovalStore`, SQLite checkpointer.
- **6 Planned Subagents**:
  1. *Research Subagent*: Public web extraction, read-only RAG, read-only approved MCP.
  2. *Document-Analysis Subagent*: BRICK-007 normalized docs, BRICK-009 retrieval, table/provenance ops.
  3. *Analytics Subagent*: Analytics data, SEO datasets, spreadsheets, RAG.
  4. *Browser-Operator Subagent*: Deterministic Playwright, approved OpenCLI tools, owner takeover.
  5. *Coding Subagent*: Sandboxed repo ops, GitHub MCP, test runners, narrow file ops.
  6. *Report-Generation Subagent*: Retrieved evidence, approved document tools, citation validator.
- **Subagent Contract**: Explicit task, schema, narrow tool allowlist, token/cost budgets, cancellation propagation, and parent authority.

### 3.5 BRICK-012: Real-Time English and Arabic Voice
- **Primary Media Transport**: LiveKit.
- **Primary VAD**: Silero VAD.
- **Primary Local STT Candidate**: `faster-whisper`.
- **Primary English TTS Candidate**: Kokoro.
- **Lightweight Fallback TTS Candidate**: Piper.
- **Arabic TTS Candidate**: Benchmark-selected Arabic TTS engine.
- **Reference-Only Architectures**: `S-P-A-C-E-B-A-R/VoxBigBrain`, `Madhurelision/AI_assist`.
- **Pipeline & Routing**: Microphone -> LiveKit -> Silero VAD -> faster-whisper -> language detection -> LangGraph agent -> English/Arabic TTS router -> LiveKit playback -> speaker. Instant barge-in (< 50ms).
- **Language Scope**: English and Arabic only.

## 4. Explicitly Removed Technologies & Architectures

The following items are formally removed from the roadmap, task backlog, and planned architecture by Project Owner decision:

1. **Microsoft Fabric MCP Server** — `REMOVED BY PROJECT OWNER DECISION`
   - *Rationale*: Enterprise cloud-specific scope outside core local-first and governed architecture; unapproved external SaaS dependency.
2. **Azure MCP Server** — `REMOVED BY PROJECT OWNER DECISION`
   - *Rationale*: Proprietary cloud-platform coupling violating FOSS-first, model-agnostic, and local-first architecture principles (Rule 1, Rule 4).
3. **beyahcuruk-del/captcha-takeover** — `REMOVED BY PROJECT OWNER DECISION`
   - *Rationale*: Security-challenge detection and human takeover must be implemented natively within JAVED (Rule 1, Rule 3, Rule 4); no unvetted external takeover wrappers.
4. **scrapfly/Antibot-Detector** — `REMOVED BY PROJECT OWNER DECISION`
   - *Rationale*: Stealth bot-detection evasion violates core operational constraints (human takeover, not security bypass); JAVED does not evade anti-bot measures.
5. **rebrowser/rebrowser-bot-detector** — `REMOVED BY PROJECT OWNER DECISION`
   - *Rationale*: Fingerprint spoofing and bot-detection patching violate Rule 4 and security principles; native owner takeover is the sole authorized path for security challenges.
6. **Urdu Language Support** — `REMOVED BY PROJECT OWNER DECISION`
   - *Rationale*: Voice, STT, TTS, memory, and RAG capabilities are formally bounded to English and Arabic to ensure acoustic quality, reliable diacritics/tashkeel handling, and high-fidelity benchmarked evaluation without unsupported models or synthetic artifacts.

## 5. Consequences & Next Steps

- This ADR governs documentation, specifications, and planning for BRICK-008 through BRICK-012.
- It does **not** authorize immediate implementation, dependency installation, package addition, browser extension setup, or model downloads.
- Each future brick must proceed sequentially through preflight, architecture review, owner authorization, phased implementation, live verification, acceptance report, and owner sign-off.
