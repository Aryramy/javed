# ADR-006: Web and Document Extraction Pipeline

> **Status**: ACCEPTED (PHASE 0 EVALUATED)  
> **Date**: 2026-10-29  
> **Deciders**: Principal Architect, Content Extraction Lead & Project Owner  
> **Impact Area**: Document Understanding, Web Scraping, Normalized Intermediate Extraction (BRICK-007)  

---

## 1. Context & Problem Statement

Project **Javed (New JARVIS)** must extract structured, accurate information from two primary sources:
1. **Web Pages**: Dynamic SPAs, news articles, documentation sites, and blogs.
2. **Local & Uploaded Documents**: PDFs (including multi-column, complex layout, and scanned documents), Microsoft Word (`.docx`), and Excel spreadsheets (`.xlsx`).

Traditional approaches using basic regex, generic `pypdf`, or `pdfplumber` fail catastrophically on tables, complex reading orders, equations, and multi-column research papers. Conversely, sending raw PDFs as images to multimodal LLMs is cost-prohibitive for large documents.

---

## 2. Options Considered & Technology Evaluation

### 2.1 Web Extraction: Crawl4AI vs Generic BeautifulSoup / Playwright Scraper
- **Selection**: **Crawl4AI** (Open Source, MIT / Apache 2.0).
- **Rationale**: Crawl4AI is built specifically for AI agents and LLMs. It handles headless browser rendering, cookie popups, anti-bot heuristics, extracts clean semantic Markdown, and generates structured JSON with extracted media, metadata, and link graphs.

### 2.2 Document Extraction: Docling vs Unstructured vs PyPDF
- **Candidate A: `Docling` (by IBM Research) (SELECTED)**:
  - Open source (MIT licensed).
  - State-of-the-art layout analysis using specialized vision models (TableFormer for table structure extraction, reading order decoders).
  - Native multi-format support: PDF, DOCX, XLSX, PPTX, HTML, AsciiDoc.
  - Produces unified `DoclingDocument` representation convertible to Markdown, JSON, or chunked text with exact bounding box provenance.
- **Candidate B: `Unstructured` (REJECTED AS CORE)**:
  - Heavyweight dependencies; frequently pushes towards proprietary hosted API keys.
- **Candidate C: `PyPDF` / `pdfplumber` (REJECTED FOR COMPLEX PARSING)**:
  - Destroys multi-column reading order and cannot accurately parse complex nested tables.

---

## 3. Decision

We approve **Crawl4AI** for web extraction and **Docling** for document understanding.

### Pipeline Architecture:
1. **Web Pipeline**:
   - URL -> `Crawl4AI` -> Clean Markdown + Structured Metadata + Extracted Media -> Ingestion / Agent Context.
2. **Document Pipeline**:
   - File (`.pdf`, `.docx`, `.xlsx`) -> `Docling` -> Layout & Table Analysis -> Clean Markdown with Table Preservation -> Provenance Annotations (Page numbers, Bounding boxes) -> Vector Chunker / Agent Context.
3. **Quality & Limitation Guardrails**:
   - Scanned PDFs: Automatically detect image-only pages and route through local OCR (Tesseract / EasyOCR).
   - Provenance Tracking: Every extracted fact or table must retain source metadata (document filename, page number, sheet name, cell range).
   - Extraction Error Reporting: If extraction confidence is low (< 0.7) or tables are truncated, the system warns the user and Developer Mode displays the parsing diagnostic.

---

## 4. Consequences & Trade-offs

### Positive
- Exceptional table extraction quality for financial statements and spreadsheets.
- Strict provenance tracking enables the agent to cite exact page numbers and document sources.
- 100% open-source local processing: documents never leave the local machine for parsing.

### Negative / Mitigations
- Docling model weights require local disk storage (~1-2 GB for vision models) and CPU/GPU memory during inference. *Mitigation*: Run Docling parsing asynchronously in background thread pools; cache parsed documents as SQLite records to prevent re-parsing.

---

## 5. Phase 0 Preflight & Compatibility Findings (2026-10-29)

During BRICK-007 Phase 0 preflight, dependency resolution was validated against the active Windows 11 Python 3.12.15 environment via `uv pip compile`:
1. **Zero Conflict Resolution**: 153 transitive packages resolved cleanly in 3.75s with `pydantic v2.14.1`, `playwright v1.64.1`, and `torch` (with PyTorch version requiring strict stable CPU wheel auditing in Phase 1).
2. **Offline Fallback Architecture**: If HuggingFace model download fails or is unavailable, Docling gracefully falls back to `PdfFormatOption` plus `PyPdfiumDocumentBackend` with model-backed stages disabled where supported, allowing lightweight text and table extraction without vision models.
3. **Normalized Intermediate Model**: All extractions map into canonical `NormalizedDocument` Pydantic model (implemented in Phase 2 in `src/javed/extraction/schema.py`) retaining content SHA-256 hashes, elements, structured tables, and provenance.
4. **Security Enforcement Separation**: Existing SSRF IP gating (`BrowserSecurityGuard` from BRICK-006) is reused for web crawls; file size, page count, and OOXML ZIP internal inspection are planned for Phase 3 (`ExtractionSecurityGuard`).
5. **Boundary Isolation**: BRICK-007 handles ingestion and extraction only. Chunking, embeddings, and vector indexing are deferred to BRICK-009.

---

## 6. Reversal Conditions

This decision would be reconsidered if Docling becomes unmaintained or fails to run efficiently on standard non-GPU Windows workstations, in which case lighter fallback parsers (e.g. `pymupdf4llm`) will be evaluated.
