# ADR-001: Backend Architecture, Runtime, and Tooling

> **Status**: PROPOSED (PENDING OWNER APPROVAL)  
> **Date**: 2026-10-22  
> **Deciders**: Principal Architect (Subject to Project Owner Review)  
> **Impact Area**: Core Backend, API Gateway, Agent Runtime  

---

## 1. Context & Problem Statement

Project **Javed (New JARVIS)** requires a high-performance, asynchronous, type-safe, and developer-friendly backend runtime capable of orchestrating complex AI agent loops, executing sandboxed tools, running browser automation scripts, handling real-time WebSocket/SSE streams, and interfacing seamlessly with leading open-source AI and data libraries.

We evaluated two primary runtime candidates:
- **Option A**: Python 3.12+ with FastAPI, Pydantic v2, HTTPX, SQLAlchemy, Alembic, and `uv`.
- **Option B**: Node.js 20+ with TypeScript, Express/Fastify, and Prisma/Drizzle.

---

## 2. Options Considered & Evaluation Criteria

| Evaluation Criterion | Option A: Python 3.12 + FastAPI + uv | Option B: Node.js 20+ + Fastify / TypeScript |
|---|---|---|
| **AI/Agent Ecosystem Native Support** | **Superior**: Native home of LangGraph, Deep Agents, Docling, Crawl4AI, Browser Use, Faster-Whisper, and PyTorch. | **Moderate**: Many AI frameworks are Python-first; Node.js ports often lag behind or require sub-processing Python scripts. |
| **Data & Document Processing** | **Superior**: Direct integration with Docling, Pandas, openpyxl, python-docx, and NumPy without cross-process IPC. | **Moderate**: Limited high-fidelity document parsing compared to Python's data ecosystem. |
| **Package Management & Tooling Speed** | **Excellent**: `uv` (written in Rust) provides 10x-100x faster package resolution/installation than traditional pip/poetry. | **Excellent**: `npm`/`pnpm` are mature and fast. |
| **Asynchronous I/O & Streaming** | **Excellent**: Python `asyncio` + FastAPI native support for WebSockets, SSE, and streaming responses. | **Excellent**: Node.js event loop handles concurrency natively. |
| **Type Safety & Data Validation** | **High**: Pydantic v2 (Rust-backed core) provides strict runtime parsing and compilation-level typing with mypy/Ruff. | **High**: TypeScript static typing; Zod for runtime validation. |
| **Windows Portability (Non-Admin)** | **High**: `uv` manages Python versions and isolated virtual environments in user space without requiring administrator elevation. | **High**: `nvm-windows` or standalone Node operates cleanly in user space. |

---

## 3. Decision

We adopt **Option A: Python 3.12+ with FastAPI and `uv`** as the backend runtime and architecture for Javed.

### Core Stack Components:
1. **Runtime**: Python 3.12 (managed via `uv`).
2. **API Framework**: FastAPI for high-performance REST endpoints and WebSockets.
3. **Data Validation & Schemas**: Pydantic v2 for typed request/response models and tool schemas.
4. **HTTP Client**: HTTPX for asynchronous, connection-pooled outbound requests to OpenRouter and external services.
5. **Persistence / ORM**: SQLAlchemy 2.0 (asyncio-compatible) with Alembic for database schema migrations.
6. **Code Quality**: Ruff for ultra-fast linting and code formatting; mypy for strict static type checking.
7. **Task Execution**: Python `asyncio` native task groups and timeouts.

---

## 4. Consequences & Trade-offs

### Positive
- Direct, in-process access to state-of-the-art AI libraries (LangGraph, Crawl4AI, Docling, Browser Use) without inter-process communication overhead.
- Lightning-fast dependency management with `uv`.
- Standardized typed schemas via Pydantic v2 shared across tool definitions, agent states, and API contracts.

### Negative / Mitigations
- Full-stack developer must context-switch between Python (backend) and TypeScript (frontend). *Mitigation*: Generate TypeScript client types directly from FastAPI OpenAPI schema via automated code generation in CI/CD.
- Python Global Interpreter Lock (GIL) for CPU-bound tasks. *Mitigation*: Python 3.12 I/O is asynchronous; CPU-bound document parsing or local whisper inference runs in dedicated thread/process pools.

---

## 5. Reversal Conditions

This decision would be reconsidered only if Python-based agent orchestration frameworks become unmaintained, or if end-to-end TypeScript compilation delivers demonstrable 5x latency reductions across all tool-calling pipelines without losing access to Docling and Crawl4AI.
