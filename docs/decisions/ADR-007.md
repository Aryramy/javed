# ADR-007: Multilingual Voice Architecture, Pipeline & Provisional Models

> **Status**: PROPOSED (PENDING OWNER APPROVAL)  
> **Date**: 2026-10-22  
> **Deciders**: Principal Architect & Multimodal Audio Lead (Subject to Project Owner Review)  
> **Impact Area**: Voice Conversation, Speech-to-Text, Text-to-Speech, Audio I/O  

---

## 1. Context & Problem Statement

Project **JARVIS (Project Javed)** requires a real-time, multilingual conversational voice system with:
1. Automatic language detection and switching between **Urdu, English, and Arabic**.
2. Natural mixed-language code-switching (e.g. Urdu/English hybrid phrases common in colloquial speech).
3. Low end-to-end conversational turn-around latency.
4. Voice Activity Detection (VAD) and immediate barge-in / interruption capability.
5. High-quality, natural human-like speech synthesis without robotic cadences.
6. Decoupled, provider-independent adapter interfaces allowing seamless substitution between remote API gateways and local offline engines.

The environment contains preliminary configuration for remote audio models accessible via the OpenRouter gateway (`https://openrouter.ai/api/v1`).

## 2. Provisional OpenRouter Voice Models & Performance Realities

### 2.1 Provisional Voice Model Configuration
The OpenRouter gateway exposes provisional remote audio models:
- **Speech-to-Text (STT)**: `openai/whisper-large-v3-turbo`
- **Text-to-Speech (TTS)**: `elevenlabs/eleven-v4-turbo` (Voice: `george`)
- **API Endpoint**: `https://openrouter.ai/api/v1`

### 2.2 Commercial Gateway vs Direct SaaS Distinction
- **OpenRouter Gateway Access**: The `elevenlabs/eleven-v4-turbo` model is accessed through the already-approved OpenRouter gateway using standard per-token credits under Rule 3 ([RULES.md](file:///c:/Users/arehman/Desktop/AI Projects/Javed/docs/RULES.md)).
- **No Direct SaaS Dependency**: This does **not** introduce a separate proprietary ElevenLabs account, commercial SaaS contract, or direct ElevenLabs API key, maintaining architectural independence.

### 2.3 Crucial Principle: API Availability != Real-Time Conversational Feasibility
> [!CAUTION]
> The mere availability of STT and TTS models on an external API endpoint does **not** prove they can deliver an acceptable conversational voice experience:
> 1. **Round-Trip Latency**: Sequential remote STT -> LLM -> TTS calls over the internet can easily introduce 2.5s - 5.0s total latency, which breaks natural conversational flow.
> 2. **Streaming Audio Chunking**: TTS synthesis must support token-streaming audio generation rather than waiting for complete sentence or paragraph completions.
> 3. **Phonetic & Multilingual Realities**: While Whisper handles Urdu and Arabic speech recognition well, remote TTS models must be verified empirically for natural pronunciation, diacritics, and accent accuracy in Urdu and Arabic.
> 4. **Barge-in / Interruption**: Immediate audio cut-off requires local client-side VAD (Silero VAD) to cancel outbound streams within 50ms, regardless of whether the backend TTS is remote or local.

## 4. Decision: Provider-Independent Voice Architecture

We approve a **Provider-Independent, Dual-Path Multilingual Voice Architecture**:

```mermaid
flowchart LR
    Mic[Microphone Input] --> VAD[Silero VAD (Local ONNX)]
    VAD --> |Speech Segment| STT_Adapter[Provider-Independent STT Adapter]
    
    STT_Adapter --> |Remote Path| WhisperRemote["OpenRouter: openai/whisper-large-v3-turbo"]
    STT_Adapter --> |Local Path| WhisperLocal[Faster-Whisper Local CTranslate2]
    
    STT_Adapter --> |Transcript + Language Tag| Agent[Deep Agents / LangGraph Core]
    Agent --> |Streaming Text Response| TTS_Adapter[Provider-Independent TTS Adapter]
    
    TTS_Adapter --> |Remote Path| ElevenRemote["OpenRouter: elevenlabs/eleven-v4-turbo (voice: george)"]
    TTS_Adapter --> |Local English Path| KokoroLocal[Kokoro-82M Local]
    TTS_Adapter --> |Local Multilingual Path| EvaluatedTTS["Local TTS Candidate (Evaluating in BRICK-012)"]
    
    ElevenRemote --> AudioOut[Web Audio API Speaker Stream]
    KokoroLocal --> AudioOut
    EvaluatedTTS --> AudioOut

    UserInterrupt[User Speaks / Barge-in] --> |VAD Interrupt Signal| AudioOut
    UserInterrupt --> |Cancel Generation| Agent
```

### Architectural Mandates:
1. **Provider-Independent Adapters**:
   - `AudioSTTAdapter`: Defines an abstract `transcribe(audio_bytes: bytes, language: Optional[str]) -> AudioTranscript` interface.
   - `AudioTTSAdapter`: Defines an abstract `synthesize_stream(text_stream: AsyncIterator[str], voice: str, language: str) -> AsyncIterator[bytes]` interface.
   - Core agent logic interacts solely with these interfaces, allowing instant switching between OpenRouter endpoints and local engines without modifying business logic.
2. **Unified Trilingual Persona**:
   - The assistant does not switch between different persona configurations for English, Urdu, and Arabic. The same JARVIS persona dynamically detects input language and replies in kind.
3. **Measurable Voice Acceptance Targets (BRICK-012)**:
   - Target language detection accuracy > 95% across English, Urdu, and Arabic.
   - Target end-to-end conversational turn-around latency: < 1.2s round-trip.
   - Target time-to-first-audio-chunk: < 800ms.
   - Target barge-in speech cut-off: speaker audio muted within 50ms of user speech detection.
   - Intelligible, natural pronunciation in Urdu and Arabic verified with recorded audio evidence.
4. **Strict Scope Discipline**:
   - Zero API calls, zero audio package installations, zero credential tests, and zero implementation code during BRICK-000. All voice engineering is scheduled for **BRICK-012**.

## 5. Consequences & Trade-offs

### Positive
- Provisional OpenRouter models allow immediate voice prototyping in BRICK-012 without heavy local GPU weights.
- OpenRouter access avoids a direct proprietary ElevenLabs SaaS subscription.
- Clean adapter design ensures the system can pivot to superior local open-weight speech models as the ecosystem matures.

### Negative / Mitigations
- ElevenLabs TTS usage via OpenRouter consumes token credits. *Mitigation*: Track audio usage against configurable budget ceilings in the model adapter.

---

## 6. Reversal Conditions

This decision would be reconsidered if low-latency native Speech-to-Speech (S2S) multimodal models render separate STT and TTS pipelines obsolete while providing verified Urdu and Arabic fluency.
