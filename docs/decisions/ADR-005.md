# ADR-005: Dual-Engine Browser Automation Architecture

> **Status**: PROPOSED (PENDING OWNER APPROVAL)  
> **Date**: 2026-10-22  
> **Deciders**: Principal Architect & Browser Automation Lead (Subject to Project Owner Review)  
> **Impact Area**: Browser Automation, Web Interaction, Security Sandboxing  

---

## 1. Context & Problem Statement

Project **Javed (New JARVIS)** requires computer browser automation to perform two distinct classes of web tasks:
1. **Deterministic Web Automation**: Known URLs, predictable workflows, direct DOM data scraping, file downloads, form submissions, and screenshot capture.
2. **Exploratory & Intelligent Web Navigation**: Unfamiliar website layouts, dynamic multi-page workflows, visual element localization, and contextual goal achievement.

Relying exclusively on an LLM vision agent for predictable tasks wastes tokens, introduces high latency, and suffers from non-deterministic failures. Conversely, hardcoded Playwright scripts cannot handle unfamiliar dynamic websites.

---

## 2. Options Considered & Division of Responsibilities

We evaluated browser automation frameworks and defined a dual-engine architecture:

### 2.1 Engine A: Deterministic Engine — Playwright Python
- **Role**: Predictable, scripted browser operations.
- **Characteristics**: Fast, lightweight, zero token consumption, deterministic selectors (CSS, XPath, text), automatic waiting, network interception, headless/headful modes.
- **Use Cases**:
  - Direct URL navigation and DOM content fetching.
  - Form filling on recognized platforms.
  - PDF/file downloading.
  - Capturing viewport screenshots for UI verification.

### 2.2 Engine B: Intelligent Navigation Engine — Browser Use
- **Role**: Open-ended, vision-assisted, intelligent web exploration.
- **Characteristics**: Uses multi-modal vision LLMs to inspect the visual DOM tree, reason about interactive elements, and click/type iteratively to fulfill open-ended objectives.
- **Use Cases**:
  - Finding specific products or information on unfamiliar e-commerce sites.
  - Multi-step interactive flows without static selectors.
  - Handling dynamic popups, consent dialogs, and nested iframes.

---

## 3. Decision

We approve a **Dual-Engine Browser Architecture** where **Playwright Python** handles deterministic tasks and **Browser Use** handles exploratory navigation.

### Architecture & Safety Invariants:
1. **Isolated Browser Contexts**:
   - Each agent browser session operates in an ephemeral, isolated Playwright browser context (`browser.new_context()`).
   - Cookies, local storage, and session caches are disposed of upon task completion unless explicitly marked as a saved profile by the user.
2. **Permission Boundaries & Human-in-the-Loop**:
   - Any financial transaction, checkout button, credentials submission, or file download requires explicit human confirmation via the UI modal.
3. **Real Browser Visibility**:
   - Browser actions stream live viewport frames or step screenshots to the JARVIS UI (both User Mode preview and Developer Mode inspector).
4. **Failure Boundaries & Timeouts**:
   - Strict action timeouts (default 15s per DOM action) and task limits (maximum 25 steps for Browser Use loops).
   - Graceful fallback: If an intelligent navigation step fails 3 times, the agent aborts and asks for human guidance.

---

## 4. Consequences & Trade-offs

### Positive
- Maximum cost efficiency: 80% of routine web requests use zero LLM tokens via Playwright.
- High resilience: Complex unfamiliar sites are handled autonomously via Browser Use.
- User visibility: Real browser preview in the UI eliminates blind execution anxiety.

### Negative / Mitigations
- Managing Chromium dependencies on Windows. *Mitigation*: Use `playwright install chromium` inside the local virtual environment without requiring system-wide admin privileges.

---

## 5. Reversal Conditions

This division would be revisited only if multimodal web agent models achieve <100ms latency and sub-cent operational costs, rendering deterministic scripting obsolete.
