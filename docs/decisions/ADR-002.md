# ADR-002: Frontend Architecture & UI Frameworks

> **Status**: PROPOSED (PENDING OWNER APPROVAL)  
> **Date**: 2026-10-22  
> **Deciders**: Principal Architect & Full-Stack Lead (Subject to Project Owner Review)  
> **Impact Area**: Web Client, User Interface, Developer Tools  

---

## 1. Context & Problem Statement

Project **Javed (New JARVIS)** requires a modern, responsive, highly aesthetic web interface capable of serving two distinct modes:
1. **User Mode**: Natural chat, streaming token output, task progress visualization, live browser preview, document results, human approval modals, and voice interaction.
2. **Developer Mode**: Detailed agent state inspection, tool execution timelines, raw token metrics, cost/latency counters, system health, and audit logs.

We evaluated UI component frameworks, chat interfaces, styling engines, and real-time state synchronization mechanisms.

---

## 2. Options Considered & Critical Evaluations

### 2.1 Core Framework & Bundler
- **Selection**: **React 18/19 with TypeScript (Strict Mode) and Vite**.
- **Rationale**: Vite provides instant hot-module replacement (HMR) and optimized esbuild bundling. React's ecosystem provides unmatched community support for streaming AI interfaces and complex data grids.

### 2.2 Styling & Design System
- **Selection**: **Tailwind CSS + shadcn/ui + Lucide Icons**.
- **Rationale**: shadcn/ui provides accessible, unstyled Radix UI primitives with Tailwind CSS classes copied directly into the codebase. This allows complete styling ownership without locking into an unmaintainable external component library.
- **Aesthetic Compliance**: Satisfies [UI_STANDARDS.md](file:///c:/Users/arehman/Desktop/AI Projects/Javed/docs/UI_STANDARDS.md) (dark mode palette, glassmorphism, micro-animations, accessible focus rings).

### 2.3 Chat Interface: `assistant-ui` vs `CopilotKit`
- **Candidate A: `assistant-ui` (PREFERRED / PROPOSED)**:
  - Open-source (MIT license). Modular, unopinionated, production-ready React component library specifically designed for conversational AI and agent task threads.
  - Provides thread management, message lists, streaming markdown renderers, token-by-token autoscroll, and customizable tool call components.
  - Native integration with Tailwind CSS and shadcn/ui.
  - Connects directly to our FastAPI WebSockets and SSE streaming feeds without imposing an intermediate runtime.
- **Candidate B: `CopilotKit` (NOT SELECTED)**:
  - Open-source core (MIT license). High-quality framework primarily architected for embedded application copilots, sidebars, and in-app document co-editing.
  - While it can be self-hosted, it introduces its own specialized runtime abstractions and state protocols that add unnecessary complexity when wrapping an existing FastAPI + LangGraph architecture.
  - `assistant-ui` provides a simpler, more direct fit for our standalone personal assistant interface.
- **Archived Tool UI Check**: Per project instruction, we strictly **do not** depend on the archived `assistant-ui/tool-ui` repository as a core dependency. Custom tool renderers are implemented natively using maintained `assistant-ui` and `shadcn/ui` primitives.

### 2.4 State Management & Event Streaming: AG-UI Evaluation
- **Evaluation**: AG-UI provides agent-to-frontend event streaming. However, standard Server-Sent Events (SSE) and native WebSockets combined with TanStack Query and `assistant-ui`'s native runtime adapters (`useExternalMessageConverter` or custom `ChatModelAdapter`) provide a direct, zero-overhead bridge to LangGraph's native `astream_events` (v2).
- **Decision**: Standardize on **FastAPI WebSockets / SSE** directly connected to React state via **TanStack Query** and **assistant-ui** hooks. AG-UI is deferred unless custom streaming requirements cannot be fulfilled by native SSE/WebSockets.

---

## 3. Decision

We approve the following frontend stack:
1. **Core**: React + TypeScript (strict mode) powered by Vite.
2. **Styling**: Tailwind CSS + shadcn/ui (Radix UI primitives).
3. **Chat Components**: `assistant-ui` with custom tool renderers.
4. **State Management**: TanStack Query (React Query) for server-state caching, combined with Zustand for client-side mode toggles (User Mode vs Developer Mode).
5. **Real-Time Transport**: Native WebSockets for interactive bidirectional sessions (approvals, barge-in) and SSE for resilient streaming feeds.
6. **Icons & Animations**: Lucide React icons; Motion (Framer Motion) for micro-animations.

---

## 4. Consequences & Trade-offs

### Positive
- Production-grade accessibility and modern dark aesthetic out-of-the-box via shadcn/ui.
- Decoupled from proprietary cloud runtimes.
- Clear separation between User Mode and Developer Mode views on top of a single unified React application shell.

### Negative / Mitigations
- Rapid updates in AI UI libraries. *Mitigation*: shadcn/ui code lives directly in `src/components/ui/`, giving us permanent source control and zero vendor lock-in.

---

## 5. Reversal Conditions

This decision would be reversed only if `assistant-ui` becomes unmaintained or incompatible with standard React/Tailwind releases, in which case custom chat components will be built directly atop Radix UI and Tailwind CSS.
